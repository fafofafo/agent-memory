# Token 节省实测分析报告 —— 基于真实会话数据

**分析对象**: 本 WeCom 对话（14 轮，含 28 次工具调用）
**分析方法**: 解析 DSH 会话日志 `session.jsonl`，按 DeepSeek 系 tokenizer 启发式估算（中文 1 字≈1 token，英文≈4 字符/token）
**模拟工具**: Agent Memory 记忆系统（`agent-memory/`，记忆注入成本为实测值）

---

## 一、会话实测统计

| 指标 | 数值 |
|---|---|
| 对话轮数 | 14 |
| 用户消息 | 14 条 |
| 助手消息（含 reasoning 思考） | 32 条 |
| 工具调用 / 工具结果 | 28 次 / 27 条 |
| 对话总 token | **73,169** |
| 其中助手输出（含思考链 reasoning） | 41,165（占 56%） |
| 单轮最大 | 38,382（写代码轮，工具调用 12,343） |

**关键发现**：这个对话的 token 大头是**思考链（reasoning）+ 工具调用**，不是用户消息。工具调用/结果是历史中反复被携带的最重部分。

---

## 二、两种场景模拟

**场景 A（无记忆）**：每轮输入 = 系统提示 + 累计全部历史（工具结果、思考链全量携带）
**场景 B（记忆注入）**：每轮输入 = 系统提示 + 当前用户消息 + 检索注入 top-5 记忆（实测每条 21 token + 格式开销 ≈ 232 token/轮）

| 场景 | 累计输入 token |
|---|---|
| A 无记忆 | 228,319 |
| B 记忆注入 | 28,910 |
| **节省** | **199,409 token（87.3%）** |

最后一轮对比：A 需携带 73,169 token 历史，B 仅需约 2,032 token。

---

## 三、金额估算（本会话）

| 定价 | 场景 A | 场景 B | 节省 |
|---|---|---|---|
| DeepSeek（$0.27/M 输入） | $0.06 | $0.01 | $0.05 |
| GPT-4o 级（$2.5/M） | $0.57 | $0.07 | $0.50 |
| Claude 级（$3/M） | $0.68 | $0.09 | $0.59 |

> ⚠️ 本会话金额很小——**单次短对话的绝对节省有限**，记忆系统的价值在长期/多会话场景。

---

## 四、外推：1000 轮 / 记忆库膨胀到 200k token

假设每轮对话量 ~1,200 token（含工具），记忆库持续沉淀至 200k token：

| 场景 | 累计输入 |
|---|---|
| A 无记忆（128k 窗口截断后） | 123,269,200 |
| B 记忆注入（top-5 × 200 token） | 3,160,000 |
| **节省** | **97.4%** |

金额：DeepSeek 定价省 **$32**；GPT-4o 级定价省 **$300**。

---

## 五、诚实的边界说明

1. **理想化假设**：场景 B 假设每轮完全不带历史（纯无状态 + 记忆注入）。真实接入通常保留"近期 2-3 轮滑动窗口"以保对话连贯，节省率会降至 **60-80%** 区间，但更稳健。
2. **本会话金额小的原因**：绝对 token 量小（73k）。省 token 的百分比很高，但换算成钱在 DeepSeek 定价下不明显——**在长对话、高频使用、或昂贵模型（GPT-4o/Claude 级）下才有显著金额意义**。
3. **记忆维护成本**：沉淀记忆若用 LLM 摘要会吃掉部分节省；本实现用纯文本落盘（零 LLM 成本），注入检索也用本地打分（不调 embedding API），所以 B 场景的开销是纯固定小开销。
4. **检索质量决定收益**：检索不准会注入无关内容，白费 token 且降质量。
5. **输出 token 不省**：助手生成内容（含思考链）两场景相同，本报告只对比输入侧。

---

## 六、结论

- **输入 token 节省率：87%（本会话实测）~ 97%（长期外推）**
- **金额意义**：DeepSeek 定价下短期不明显（<$1），长期/高频或贵模型下显著（$32 ~ $300+/千轮）
- **最大价值**：突破上下文窗口限制——128k 窗口下，无记忆方案到后期会**截断丢弃早期记忆**，而记忆方案永不超窗、早期信息可通过检索召回
